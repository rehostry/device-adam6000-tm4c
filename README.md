# device-template — a copy-and-fill scaffold for a new rehostry device

This is **not a runnable device.** It is a skeleton, faithful to the canonical
[`device-plc`](../device-plc), that you **copy, rename, and fill** to build a new
standalone, pip-installable HALucinator device. Every file carries the AGPL
header and uses the literal placeholder tokens **`adam6000-tm4c`** (the device slug) and
**`rehostry_adam6000_tm4c`** (the Python package). Anywhere a device-specific decision
is required is marked `TODO:`.

> **Fullest worked example:** [`device-plc`](../device-plc) — a subprocess device
> with a bp_handler UART→Modbus bridge, a self-booting attack proven by
> firmware-memory read-back, and a polling web panel. Also read the top-level
> [`adam6000-tm4c-PLAYBOOK.md`](../adam6000-tm4c-PLAYBOOK.md) end to end before you start.

## How to use this template

### 1. Copy and rename

```bash
cp -r device-template device-<slug>
cd device-<slug>

# rename the package directory + the panel module
git mv src/rehostry_adam6000_tm4c src/rehostry_<slug>            # (or plain mv)
git mv src/rehostry_<slug>/adam6000_panel.py src/rehostry_<slug>/<slug>_panel.py
git mv src/rehostry_<slug>/configs/adam6000_tm4c_config.yaml \
       src/rehostry_<slug>/configs/<slug>_config.yaml

# replace every placeholder token (slug uses underscores in the package,
# hyphens in the distribution/console-script names)
grep -rl 'adam6000-tm4c' . --include='*.py' --include='*.toml' --include='*.yaml' \
     --include='*.md' --include='*.in' | xargs sed -i '' \
     -e 's/rehostry_adam6000_tm4c/rehostry_<slug_underscore>/g' \
     -e 's/rehostry-adam6000-tm4c/rehostry-<slug_hyphen>/g' \
     -e 's/device-adam6000-tm4c/device-<slug_hyphen>/g' \
     -e 's/adam6000-tm4c/<slug>/g'      # do this LAST; review the diff
```

(`sed -i ''` is the macOS form; on Linux use `sed -i`.) Review the diff — the
bare `adam6000-tm4c` token also appears in prose and env-var names you may want to hand-tune.

### 2. Bring up the firmware

1. Fill `tools/extract_firmware.py` (`EXPECT_INIT_SP`/`EXPECT_RESET`, package
   path) and run it against your corpus ELF to write `configs/<slug>.bin` +
   `configs/<slug>_addrs.yaml`.
2. Build `configs/<slug>_config.yaml` from scratch via bare-march (playbook §3):
   run → classify the fault/busy-spin → locate the gate → model the minimum →
   re-run. `device-plc`'s config is the reference.
3. Add peripheral models (`peripheral_models/`) and bp_handlers (`bp_handlers/`)
   only where a default-0 MMIO read or a busy-wait actually blocks progress.

### 3. Earn each milestone (playbook §3) — evidence, don't assume

| level | means | evidence |
|---|---|---|
| **M1** | boots without faulting | no `UC_ERR` / `Traceback` / `FETCH-DERAIL` in the log |
| **M2** | drivers initialise | the **firmware's own** log/driver strings |
| **M3** | kernel/scheduler runs | timestamps or a loop advancing monotonically |
| **M4** | real protocol round-trip | firmware-generated bytes out, injected bytes in, seen via the firmware's own output |

Before the first boot, **derive a falsifiable prediction statically** — disassemble
the transmit path, write down the exact bytes the firmware must emit, then boot.
Put it in `PROVENANCE.md`. Record honest results in `STATUS.md`.

### 4. Meet the attack contract (playbook §2a)

`attack.py` must expose:

```python
def run_attack(on_stage=None, log_dir=None) -> dict:   # >= {"booted": bool, "landed": bool}
def main() -> int:                                     # prints exactly one  RESULT: {json}
```

- **Self-booting:** `python -m rehostry_<slug>.attack` works with nothing running
  first; it spawns its own rehost and tears down only the PIDs it started.
- **Exactly one** final `RESULT: {json}` line with at least `booted` + `landed`.
- **The oracle is the firmware's own output** — never set `landed: true` from host
  bookkeeping, never weaken a check to make a run pass.

### 5. Checklist before you call it done

- [ ] every `adam6000-tm4c` / `rehostry_adam6000_tm4c` token renamed; no placeholder left
- [ ] `tools/extract_firmware.py` regenerates the bin + addrs and **hard-fails**
      on a vector-table mismatch
- [ ] `pytest tests/` passes (config/symbol agreement + the spawn invariants;
      add device-specific couplings)
- [ ] `rehostry-<slug> run --seconds 15` boots clean (M1)
- [ ] `python -m rehostry_<slug>.attack` prints one `RESULT:` line; `landed`
      reflects real firmware-side evidence
- [ ] `STATUS.md` / `PROVENANCE.md` filled from LIVE runs (incl. the static
      prediction and whether it matched)
- [ ] firmware bytes kept out of git unless redistributable (see `.gitignore`
      / `PROVENANCE.md`)
- [ ] no `HALUCINATOR_SRC` / `PYTHONPATH` source-tree injection anywhere

## Install (what the finished device's README will say)

Install the core (dev branch) and the device into one venv, then run — no source
tree, no `HALUCINATOR_SRC`:

```bash
pip install "halucinator[unicorn] @ git+https://github.com/rehostry/halucinator.git@dev"
pip install -e .                      # this package
```

The device runs the installed `halucinator@dev` via `sys.executable` (override
with `HAL_PY=/path/to/venv/bin/python`). No `HALUCINATOR_SRC`/`PYTHONPATH`
source-tree injection.

(For co-simulation, also `pip install -e '.[orchestrator]'`.)

## Run

```bash
rehostry-adam6000-tm4c run --seconds 15                # boot + stream the HAL console
rehostry-adam6000-tm4c run --bridge --seconds 1800     # also expose the host bridge seam
rehostry-adam6000-tm4c-panel                           # the polling web panel (http://127.0.0.1:8770)
python -m rehostry_adam6000_tm4c.attack                # the self-booting attack (prints RESULT: {json})
```
